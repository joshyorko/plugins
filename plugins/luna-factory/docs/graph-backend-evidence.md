## Architectural conclusions

Keep Luna's graph, claims, acceptance evidence and run state authoritative in its existing store. Add backend descriptors before additional adapters. A descriptor must separately report advertised operations, operator enablement, qualification, authentication and entitlement. A model catalog, installed executable, configured provider, account plan string or successful transport connection cannot independently prove current subscription entitlement for a selected model. Missing evidence means unknown, not permission to fall back to API billing.

The plugin Luna runtime already owns native transport and durable identities. `Config.native_transport` accepts only `stdio` and `existing_daemon`. The latter adds `app-server proxy`; it does not create the daemon. Existing native methods include exact-turn steering/interruption, thread reads, descendants and background-terminal observation. The current policy is cooperative for native child admission; it does not enforce a pre-spawn model allowlist. Preserve these distinctions rather than promising stronger authority through descriptors. Evidence: [config.rs](https://github.com/joshyorko/plugins/blob/1ccac51591d0466250448531632b82732ddac3fe/plugins/luna-factory/server/src/config.rs#L88), [lifecycle.rs](https://github.com/joshyorko/plugins/blob/1ccac51591d0466250448531632b82732ddac3fe/plugins/luna-factory/server/src/lifecycle.rs#L529), [native.rs](https://github.com/joshyorko/plugins/blob/1ccac51591d0466250448531632b82732ddac3fe/plugins/luna-factory/server/src/native.rs#L705), [README](https://github.com/joshyorko/plugins/blob/1ccac51591d0466250448531632b82732ddac3fe/plugins/luna-factory/README.md#reconnect-and-cancellation-limits).

### CAS is reusable as an adapter boundary

CAS exposes typed control of existing daemons. It is not a planner, scheduler, workspace provisioner or replacement native runtime. Reuse its operator-owned logical target resolution and dispatch acknowledgements over its typed API. Do not transplant CAS receipt files into Luna's task database or construct a second scheduler around them.

`list_targets` only reads configured logical names/transports. `inspect_target` resolves an operator target and returns `connectivity: not_probed`; remote resolution can execute bounded read-only provider/status/config commands. It must not be described as pure filesystem-only discovery. Devsy requires exact selectors, a running workspace, identity checks and an existing TCP route; lifecycle-capable ProxyCommand/ProxyJump routes fail closed. Existing container and Kubernetes adapters select already-running workers with pinned identities. Evidence: [inspection.py](https://github.com/joshyorko/codex-action-server/blob/bf0b3823e033b9b5abd86904e0a565d6b3586206/src/codex_shared/inspection.py#L36), [boundary.py](https://github.com/joshyorko/codex-action-server/blob/bf0b3823e033b9b5abd86904e0a565d6b3586206/src/boundary.py#L86), [target tests](https://github.com/joshyorko/codex-action-server/blob/bf0b3823e033b9b5abd86904e0a565d6b3586206/tests/test_target_resolution.py).

CAS reserves a request key durably before native mutation, fingerprints the payload, uses a nonblocking OS file lock and atomically writes/fsyncs the receipt. Identical retries return the receipt without redispatch; conflicting payloads fail. An unfinished reservation remains unknown after a crash. Receipts retain native thread/turn identifiers and acknowledgement state, not prompt contents, run completion or acceptance evidence. A client must persist its key before dispatch, retain it across response loss, and reconcile native state without creating a replacement key. Evidence: [dispatch_receipts.py](https://github.com/joshyorko/codex-action-server/blob/bf0b3823e033b9b5abd86904e0a565d6b3586206/src/dispatch_receipts.py#L25), [crash/concurrency tests](https://github.com/joshyorko/codex-action-server/blob/bf0b3823e033b9b5abd86904e0a565d6b3586206/tests/test_dispatch_receipts.py#L9).

CAS offers rate-limit and usage reads, but `account/read` is explicitly deferred/unexposed. Login, logout and token refresh are excluded administrative operations. There is no raw-RPC escape hatch. Therefore a Luna CAS descriptor cannot claim full read-only auth discovery from the currently exposed API. A future typed, sanitized account read would need a reviewed contract that forces `refreshToken:false`. Even that would establish reported auth/plan state, not model entitlement. Evidence: [inspection.py](https://github.com/joshyorko/codex-action-server/blob/bf0b3823e033b9b5abd86904e0a565d6b3586206/src/codex_shared/inspection.py#L93), [native_capabilities.py](https://github.com/joshyorko/codex-action-server/blob/bf0b3823e033b9b5abd86904e0a565d6b3586206/src/native_capabilities.py#L329).

CAS's API closes the native subscription at the end of each action. Approval/user-input/tool callbacks need the originating connection. There is no durable retained-connection callback broker; an opt-in CLI approval bridge is not MCP parity. LF07 must either preserve the current native connection owner or explicitly block callbacks pending the separately scoped [CAS issue 11](https://github.com/joshyorko/codex-action-server/issues/11). Replacing Luna's persistent native observer with CAS calls would otherwise lose events and callback ownership. Evidence: [callback blocker](https://github.com/joshyorko/codex-action-server/blob/bf0b3823e033b9b5abd86904e0a565d6b3586206/docs/NATIVE_CAPABILITIES.md#callback-blocker).

Version evidence must be method-specific. At this head, `codex_rpc.py` permits all pinned experimental methods for 0.160.1, but only diagnostics and queue operations for 0.161.0. Broad exact-0.160.1 prose elsewhere is stale relative to this reviewed compatibility map. The recorded earlier PR10 blocker does not describe the entire current source head. Evidence: [compatibility map](https://github.com/joshyorko/codex-action-server/blob/bf0b3823e033b9b5abd86904e0a565d6b3586206/src/codex_rpc.py#L107), [version tests](https://github.com/joshyorko/codex-action-server/blob/bf0b3823e033b9b5abd86904e0a565d6b3586206/tests/test_native_capabilities.py), [0.161.0 acceptance note](https://github.com/joshyorko/codex-action-server/blob/bf0b3823e033b9b5abd86904e0a565d6b3586206/docs/acceptance/cas-0.161.0-native-protocol.md).

### Review remains OMP-owned

Review owns GitHub observations, bounded evidence and human mutation intent. OMP owns execution, sessions, tasks, workflow dispatch and cancellation. Its co-loaded Factory starts nothing without explicit opt-in. The OMP extension is a semantic donor, not a runtime dependency for plugin Luna.

Its capability table is deliberately narrower than the underlying OMP tool roster. Native task and eval `tool.task` admission are enforced through a wrapper. Separate eval-agent, workpool and hub-steering routes are unsupported for Factory admission/correlation. Native task cancellation remains unsupported through the public extension context. Local root effects and inherited child tools are only observed/cooperative. Do not map an OMP operation to `qualified:true` merely because a similarly named Codex operation exists. Evidence: [agentic model](https://github.com/joshyorko/review/blob/dc5d35a42e689a697a1694301d59a4ee7caced99/docs/factory/agentic-model.md), [capability table](https://github.com/joshyorko/review/blob/dc5d35a42e689a697a1694301d59a4ee7caced99/image/extension/luna-factory/omp/capabilities.ts#L35).

### Work Items is queue and artifact infrastructure

Work Items reserves input, creates parent-linked outputs, and releases inputs done/failed. The Action Server management API constructs a datadir-owned SQLite adapter. SQLite reserves with `BEGIN IMMEDIATE`, FIFO timestamp/rowid ordering and conditional state update. These are queue claims, not repository writer claims, Factory admission, native execution ownership or acceptance proof. The API does not manage arbitrary Redis/DocumentDB adapters merely because the library supports them. Keep candidate intake and result export separate from Luna's execution graph and claim ledger. Never use Work Items `DONE` to infer Factory convergence.

Evidence: [API adapter construction](https://github.com/joshyorko/actions/blob/7c98236069171f57031218f938963238986293bd/action_server/src/actions/server/_api_work_items.py#L78), [SQLite reservation](https://github.com/joshyorko/actions/blob/7c98236069171f57031218f938963238986293bd/work-items/src/actions/work_items/_adapters/_sqlite.py#L286), [canonical guide](https://github.com/joshyorko/actions/blob/7c98236069171f57031218f938963238986293bd/docs/skills/work-items.md), [SQLite tests](https://github.com/joshyorko/actions/blob/7c98236069171f57031218f938963238986293bd/work-items/tests/work_items_tests/test_sqlite_adapter.py).

## Official OpenAI capability research

Documentation was retrieved on 2026-10-08. Existing developers.openai.com Codex links redirect to official learn.chatgpt.com pages. These are current documentation observations, not qualification of an installed target.

- Native app-server uses initialized bidirectional RPC. `account/read` with `refreshToken:false` reports account information; managed ChatGPT, external tokens, API-key and Bedrock auth differ. `turn/steer` requires the active `expectedTurnId` and accepts no model/CWD/sandbox overrides. `turn/interrupt` acknowledges cancellation; subsequent completion reports interrupted status. Background-terminal list/terminate are separate experimental methods. This does not establish descendant/process cessation or rollback. Current auth guidance distinguishes local/open-source app-server authentication from commercial/hosted service use, for which Sign in with ChatGPT is the documented path. [App-server reference](https://learn.chatgpt.com/docs/app-server).
- Sign in with ChatGPT can authorize ChatGPT-plan inference through an OAuth-backed Responses provider. Its app-server example uses a caller-managed environment token and requires restarting that configured process after refresh. `model/list` may return a bundled catalog; only completed inference establishes access for that particular request. Therefore passive discovery must leave entitlement unknown, and this research does not authorize token transfer, process restart or an inference probe. [SIWC app-server guide](https://developers.openai.com/siwc/token-sharing-open-source/codex-app-server).
- `codex cloud` is documented as experimental. `cloud exec` submits with required environment ID and optional 1–4 attempts; `cloud list --json` provides task identifiers/status/cursors. It uses the main CLI's credentials. The reference does not establish a typed steer/stop/idempotent-dispatch contract or compatibility with new published-environment Cloud. Do not infer these from app-server methods. [CLI reference](https://learn.chatgpt.com/docs/developer-commands?surface=cli#cli-codex-cloud).
- New Cloud uses published environments and ChatGPT sign-in. New tasks start from prepared environment state; reopening a task continues its own work. Legacy Cloud remains the documented execution product for Code Review, GitHub and Linear integrations and is planned for deprecation. Current docs do not provide a public adapter contract that makes the two Cloud experiences interchangeable. [Cloud environment guide](https://learn.chatgpt.com/docs/environments/cloud-environments).
- `@codex review` requests GitHub review. Non-review mentions start a legacy cloud chat with PR context and may push when authorized. A posted comment is neither an idempotent native dispatch receipt nor proof of cancellation. No comment was posted during validation. [GitHub integration](https://learn.chatgpt.com/docs/third-party/github).
- The official GitHub Action is a separate CI path that installs Codex and runs `codex exec`; the documented API-key setup uses a Responses proxy. It must not be advertised as a subscription-backed native-daemon target. [GitHub Action guide](https://learn.chatgpt.com/docs/github-action).
- The Agents API is another separate hosted-harness interface. Its self-hosted sandbox runs `codex exec-server`, requires a scoped application API key and a distinct environment key, and does not use native app-server thread IDs. It is not evidence for subscription-backed LF05 dispatch. [Self-hosted Agents API sandbox guide](https://developers.openai.com/api/docs/guides/agents-api/environments/self-hosted).

## LF05 implementation and LF07 onward

Implemented only `server/src/backends.rs` and `server/tests/backends.rs` under plugin Luna, `capabilities(&Config)` returns five fixed descriptors: `native-local`, `cas-native`, `codex-cloud-cli`, `codex-cloud`, `github-codex`. No paths, credentials, environment variables, executable probes or network calls enter discovery. Only native-local is a possible planning preference, based on an already recognized transport configuration. Every descriptor has `execution_eligible:false`, unknown auth/entitlement, and no qualified execution operation. Its qualified discover operation refers only to this bounded configuration catalog. The Factory integration owns wiring and the planning-only dispatch guard; existing authorized run behavior is intentionally not retroactively rewritten.

For LF07 / tracked #61 and later adapters:

1. Keep transport, provider, auth mode, billing/entitlement and target identity as separate facts. A CAS target is not a provider or subscription. Record observation time and exact adapter/native versions when future probes exist.
2. Add a typed CAS adapter only after mapping request-key persistence, exact target/CWD/thread/turn identity, restart recovery, lost acknowledgements and terminal cessation. Reuse CAS receipts without making them the graph's source of truth.
3. Require an explicit callback ownership decision before replacing native persistent connections. An action-scoped CAS connection cannot deliver a later response to a callback on a closed connection.
4. Maintain separate native, CLI-cloud, new-Cloud, GitHub and OMP namespaces. No synthesized target IDs, implicit cloud fallback or inferred stop semantics.
5. Qualify each operation separately with exact-version fixtures and authorized live receipts. Start/steer acknowledgements prove acceptance only. Stop acknowledgement never releases a writer claim until descendants and terminals reconcile. Unknown effects retain their claims and offer read-only reconciliation.
6. Keep Work Items as optional intake/output infrastructure. Queue retry must not generate a new native request key after ambiguous acceptance or reset an existing Factory attempt budget.
