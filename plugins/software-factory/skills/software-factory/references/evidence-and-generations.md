# Evidence and generations

Every acceptance names approved generation, repository, branch, exact candidate
subject (normally a SHA), predicate, independent evaluator, source, and time.
Checks, reviews, screenshots, merges, and issue state count only when they refer
to that exact subject and still satisfy the predicate.

G approval is not G+1 approval. Preserve prior approvals and show an explainable
diff before renewal. A stale head on approval, materialize, merge, or control
intent is rejected pending fresh observation. Repair, force-push, changed
acceptance, or affected base movement invalidates acceptance. Unrelated base
movement is recorded and reevaluated only when dependencies/evidence are
affected. Post-merge closure is fresh live observation.

The implementation subject cannot certify itself. Terminalize as full outcome,
partial slice, or external/human blocker; merged code is not automatically
satisfied. Portable exports retain target, intent, generation, graph,
assumptions, constraints, appetite, fences, classifications, evidence, and
reasons. No live Actions SHA (or other transient external value) becomes
durable authority.
