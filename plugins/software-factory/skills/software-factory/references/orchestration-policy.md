# Orchestration policy

The controller is provider- and runtime-neutral. Its generic action is
**DISPATCH TO AGENT**. Use one mutation owner per lane; separate mutation from
read-only research and independent review. Capacity, appetite, repair/replan
budgets, and persistence are explicit run policy. Limits produce waiting or a
checkpoint, not filler.

An editable example preset may name a current executor/model lineup, but it is
not doctrine and cannot alter acceptance, ownership, fences, or terminalization.
Run configuration may edit executor, model, provider, effort, review mode, and
capacity only. The persistent supervisor owns the event loop and may not
silently substitute a writer, widen scope, or promote discovery. Dry-run/shadow
must expose intended effects while remaining non-mutating.
