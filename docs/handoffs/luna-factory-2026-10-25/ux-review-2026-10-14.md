# Luna Factory: adversarial product/UX review (2026-10-14)

Reviewer stance: principal product designer, Linear/Vercel/GitHub/Stripe-dashboard quality bar.
Inputs: every PNG under `~/.cache/luna-ux-review/` (main, pr94, pr94-v2 at a84a683, pr95 at 0756a31), `plugins/luna-factory/ui/src` on main, PR sources via `git show`.
The grey simulator bar and the "Host composer placeholder" are ignored throughout.
Note: `main/visual-snapshots/` (green "WORKBENCH" theme, `fullscreen-selected-node-light.png`, `fullscreen-error-light.png`, `inline-needs-input-light.png`, `mobile-*-disconnected-dark.png`) is an obsolete design. It is not the shipped UI and should be deleted from the repo so nobody reviews against it again.

---

## 1. Verdict

Luna Factory looks like an internal debugger for its own state machine, not a product. Every screen shows the server's safety rules (revisions, admission, receipts, liveness, "the server rechecks this at the action boundary") where the user's work should be. It has no type or spacing system: 7 font weights, 14 font sizes, 30+ padding values, pill-shaped everything. On the most important screen, a planned campaign, the only primary button is "Refresh planning graph". The product cannot answer "what is this, what's happening, what do I do next" in under five seconds, and that is the whole job.

## 2. Top 15 problems, ranked by user impact

### P1. The primary action on a planned plan is "Refresh". The real next step (run it) is missing.
- **View:** Campaign page, planned state. `main/dogfood-visual-snapshots/campaign-map-light.png`, `campaign-map-dark.png`, `fullscreen-planning-dark.png`, `main/live-visual-snapshots/live-campaign-map-light.png`.
- **What's wrong:** A full-width grey "PLAN NAVIGATION / Refresh planning graph / Reads the saved plan. Execution has not started. The server rechecks this at the action boundary." box, with a filled indigo **Refresh planning graph** button. Two more refresh controls sit on the same screen ("Refresh plan" in the map toolbar, and the header refresh icon). In `pr94-v2/campaign-map-light.png` the box is gone, but now the page has **no primary action at all**.
- **Why it reads as amateur:** The page's most prominent element is the system's housekeeping. Users came to make something happen. Three refresh buttons mean the UI doesn't trust its own data.
- **Fix:** One primary button in the page header, right-aligned to the title. Its label depends on state:
  - Planned, can run: **Start run**
  - Planned, can't run yet: **Set up running** (opens the one-time setup), with the caption "Luna can plan now. Running needs Codex connected." Never a dead disabled button.
  - Needs you: **Answer**
  - Running: no primary; a secondary **Stop** in the overflow (⋯).
  - Done: **Open pull request ↗**
  
  Delete the decision-panel box for every state except Needs you and Blocked. Delete the "Refresh plan" toolbar button. Keep the header refresh icon only (16px, tertiary), and auto-refresh on focus.

### P2. Jargon wall: the UI speaks the server's internal ontology
- **View:** All. Worst offenders:
  - `campaign-blocked-light.png`: "OWNED EXECUTION ISN'T PROVED STOPPED YET / Native ownership is unverified. Keep the claim held. / Reconcile native ownership / Observe existing native work without starting or stopping it."
  - `swarm-map-synthetic.png`: "NEXT SAFE ACTION / Steer the owner", "Observed native child", "admission unverified", "0 recorded attempts. 2 retained receipts recorded on this agent's thread".
  - `campaign-map-light.png`: "ACTIONS · LOCAL CANDIDATE · GITHUB EXAMPLE/ACTIONS#101 · SUPPLIED, NOT VERIFIED", "Planned · admission candidate".
- **What's wrong:** Nouns like campaign, wave, receipt, criterion, admission, candidate, native, owner, subject, claim, liveness, revision and "inference" are never defined, and they are not the user's words. Section 3 has the full glossary.
- **Why amateur:** The user has to learn the architecture before they can read a status. Stripe doesn't show "idempotency key reconciled", it says "Payment succeeded".
- **Fix:** Apply the Section 3 glossary to every string. Add a test that fails if any rendered fixture HTML contains a banned term. Exact replacements for the blocked state:
  - Title: **"Luna can't confirm the earlier run stopped."**
  - Body: "Before starting new work, Luna needs to check what's still running in Codex."
  - Primary: **Check running work**. Secondary: **Stop everything**.

### P3. Defensive disclaimers everywhere destroy trust instead of building it
- **View:** All. Examples:
  - Footer on Home and Campaign: "Status reads use no inference" / "Execution stays unavailable until independently qualified" (`live-home-campaign-light.png`, `pr94-v2/campaign-github-ready-light.png`).
  - "Shown for context only. GitHub results are not Luna proof, and nothing here can merge or integrate." (`campaign-github-ready-light.png`).
  - "Sends this run and task at its current revision only after your click. Nothing starts." (`thread-selected-dark.png`).
  - "The server rechecks this at the action boundary." (every decision panel).
- **What's wrong:** About 15% of all visible copy is liability language. It is in 11–12px faint grey (#8b919c on white, **3.2:1**, which fails WCAG AA), so it is both noise and unreadable.
- **Why amateur:** Mature products state guarantees once, in docs or a tooltip. Repeating "nothing starts" under every button makes the user wonder what *else* might start.
- **Fix:** Delete all of the strings above. Keep exactly one trust line, on the Plan composer under the button: **"Luna drafts a plan first. Nothing runs until you press Start run."** Put GitHub check results under a plain "Pull request" heading with no disclaimer.

### P4. Plan form (main) is a 10-field compliance form; PR #95 is better but still puts the wrong thing first

Buttons: Create planning graph and Start run (disabled), plus "Planning is available. Execution requires independently qualified authentication, entitlement and adapter support."

- **What's wrong (PR #95):**
  - The repo list sits *above* the text box. It is a fixed-height, internally scrolling radio list, and its last row is clipped mid-description ("joshyorko/ror … Connect" is cut in half).
  - Radio rows and Connect buttons are mixed in one list, which is two interaction models in one control.
  - "More options" still hides 7 controls: Done when, Leave alone, When it's done, Model "luna · xhigh", Workers at once, Time limit, Retries.
  - "Running it needs a one-time setup." has no link and no explanation.

  - The repo popover holds: search, "Your repos", "On GitHub" (each with Connect), and "+ New repo…".
  - "More options" contains only **When it's done** (Keep changes local / Push a branch / Open a pull request) and **Leave alone**. Move Model, Workers, Time limit and Retries to Settings as defaults.

### P5. Repo onboarding is an operator ticketing system
- **View:** main `renderRepositories` (`view.ts:261-268`): "Operator-offered repositories", "Request a trusted alias for a local repository. A local operator must approve access before it can be used.", "Give the local operator this request ID: `<code>`". Home shows "No repositories configured / Choose a local repository offered by your operator, then request access."
- **What's wrong:** A single user is asked to file a request to themselves, copy an ID, wait, then "Refresh repositories to use its alias". "Alias" is exposed as a user concept.
- **Why amateur:** No modern dev tool makes you approve your own access. Vercel: "Import Git Repository → pick → Deploy".
- **Fix:** Repos come from exactly two sources, both one click: **Connect GitHub** (OAuth/App install, then pick from the list) and **New repo** (name only). Local-path approval becomes an admin-only Settings page, hidden when no operator is configured. Delete the word "alias" from the UI. PR #95 moves in this direction. Finish it by deleting the main `repositories` editor from the user path.

### P6. Home duplicates every planned item, and its counts contradict what's on screen
- **View:** Home. `main/dogfood-visual-snapshots/home-light.png`, `live-home-campaign-light.png`, `home-campaign-mobile-dark.png`, `pr94-v2/home-light.png`.
- **What's wrong:**
  - The subtitle says "1 campaign · 1 needs you · 1 in progress · 2 in history", yet 4+ items are listed.
  - The "Parent campaigns" section shows the title "Actions v2: uv packaging and cross-platform CI" **twice**: once as the parent, and again in an indented "PLAN" child row.
  - "Planned · not started" appears twice in the same block, and "Execution hasn't started. 14 planned tasks." appears twice.
  - "No execution runs yet" is a third row of nothing.
  - Empty groups render as filler ("Needs you 0 / Nothing needs your decision.", "In progress 0 / No owned work is in progress.").
- **Why amateur:** Duplicated rows and wrong counts are the fastest way to look buggy.
- **Fix:**
  - One row per plan. Drop the "Parent campaigns" group. A plan created from an issue shows "from #101" in its meta line.
  - Groups in this order: Needs you, Running, Planned, Done (Done collapsed to a "Show 2 done" link).
  - Hide empty groups entirely.
  - Delete the subtitle count line; group headers carry their own counts.

### P7. No type, spacing or radius system
- **View:** All. Source evidence in `style.css`:
  - Font sizes: 11, 12, 13, 14, 15, 16, 21, 24, 26, 28px, plus 4 `var()` fallbacks with different defaults (13 vs 12, 17 vs 14).
  - Weights: 400, 500, **560**, 600, **620**, **640**, **650**.
  - Gaps: 2, 3, 4, 5, 6, 7, 8, 9, 10, 12, 14, 16. Paddings: 30+ unique values ("7px 13px", "9px 11px", "4px 10px 4px 4px").
  - Radii: 2, 4, 6, 8, 10, 12, 16, 999, 50%.
  - Three different page-title sizes: Home 28/650, Campaign 26/650, Editor 24/640.
- **Why amateur:** Non-standard weights like 560/620/640 render as faux-bold or snap unpredictably in host fonts. Nothing lines up, so screens feel "off" even when nobody can say why.
- **Fix:** Apply the Section 4 tokens. Ban raw px values in component CSS (lint). Use 3 weights only.

### P8. Pills and disclosures everywhere: the "slop-coded pill box" the owner hates
- **View:** Campaign page.
  - Agent roster pills ("Luna / Coordinator · Liveness unknown", "Worker 1 / Worker · Active · Observed native child") in `campaign-blocked-light.png` and `swarm-lanes-synthetic-dark.png`.
  - PR pills straddling card bottom borders ("PR #121 ●●●") in `campaign-map-light.png`.

- **What's wrong:** Four different "expand" affordances (summary triangles, pills, segmented control, cards) all look clickable. None looks like a menu. Pills overlap borders, which reads as a layout bug.
- **Fix:**
  - Buttons get radius 8. Pills (radius full) are reserved for *non-interactive* status chips only.
  - Delete the agent roster pill strip. Agents live in the Activity tab (P12).
  - The PR becomes a 12px meta line *inside* the card: "PR #121 · checks passed", with a 6px status dot. No floating pill.
  - "Other available actions" becomes a `⋯` icon button opening a menu.
  - "Edit this planned task" becomes a secondary **Edit** button opening an edit sheet.
  - "Evidence and audit" moves to a "Details" tab (or is deleted for non-admins).

## 3. Information architecture

### Primary objects (3, not 9)

| Object | What it is | Replaces |
|---|---|---|
| **Repo** | A GitHub repo or a new empty repo Luna can work in | approved repository, alias, operator-offered repository, workspace |
| **Plan** | Your request turned into tasks. Exists before anything runs. | campaign, parent campaign, planning graph, issue graph, "PLAN" child row |
| **Run** | One execution of a plan by agents; a plan can have several runs over time | run, owned execution, attempt history |

Tasks and agents are parts of a plan and a run, not navigation destinations.

### Navigation

```
Home  (composer + list of Plans grouped by state)
 └─ Plan page  (title, one primary action, tabs: Tasks | Activity | Details)
      ├─ Task drawer (right side on wide, full-screen sheet on narrow)
      └─ Edit sheet / Review change card
Settings (⋯ menu): Defaults (model, workers, time limit, retries), GitHub connection, Repos, Admin (local repos, only if operator mode)
```

- Merge **Plan work** into **Home**. The composer is always at the top of Home, which matches the owner's "jump in, pick repo, say yolo" flow and makes the empty state free.
- Delete the "Parent campaigns" group and the nested PLAN rows. Issue provenance becomes a meta link "from #101".
- Delete "Evidence and audit" for normal users. Its useful bits go into a **Details** tab: Done-when checks, pull request, model used, time used. Run identity, subject, revision, intent/dispatch generation and receipts go behind "Show technical details" (collapsed, monospace, copy button) for debugging only.
- Delete the separate repo-onboarding editor from the user path (P5).
- The inline chat card is a *pointer* to a Plan, not a mini-app (max 2 actions).

## 4. Design system spec (inside ChatGPT)

Principles: inherit host neutrals and font family (`--font-sans`). Luna owns only the accent, status hues and the moon glyphs. Everything else is host-native, so it looks like it belongs in ChatGPT.

### Type scale (rem relative to host root so host font scaling works; px at 16px root)

| Token | Size / line | Weight | Use |
|---|---|---|---|
| `--text-title` | 1.375rem (22) / 28 | 600 | Page title (Home "Plans", plan title). Letter-spacing -0.01em. Narrow: 1.125rem/24 |
| `--text-heading` | 1rem (16) / 24 | 600 | Section headings, drawer title, empty-state title |
| `--text-body` | 0.875rem (14) / 20 | 400 | Default text, list titles (500 for row titles) |
| `--text-label` | 0.8125rem (13) / 18 | 500 | Buttons, field labels, tabs |
| `--text-meta` | 0.75rem (12) / 16 | 400 | Meta lines, timestamps (tabular-nums) |
| `--text-mono` | 0.75rem (12) / 16 | 400 | Commit SHAs, IDs (technical details only) |

- Weights: 400, 500, 600 only.
- No uppercase eyebrows except one optional 11px/500 +0.04em section label per page, used for column headers only ("Step 1").
- Minimum text size 12px. Delete all 11px text.

### Spacing (4px base)
`--space-1: 4px; --space-2: 8px; --space-3: 12px; --space-4: 16px; --space-5: 24px; --space-6: 32px; --space-7: 48px.`
- Page gutter 24 (wide) / 16 (narrow).
- Section gap 24. Row padding 12/16. Control internal padding 8/12.
- Card padding 16. Inline card padding 16.

### Radii
- `--radius-sm: 6px` (chips, small controls, focus ring)
- `--radius-md: 8px` (buttons, inputs, task cards)
- `--radius-lg: 12px` (panels, inline card, drawer)
- `--radius-full` only for status dots, avatars and non-interactive status chips.
- **No pill buttons.**

### Borders and elevation
- 1px `--line` for all dividers and cards. `--line-strong` only for inputs and hovered cards.
- Elevation: flat by default. Popovers/menus: `0 4px 16px rgba(0,0,0,.10), 0 0 0 1px var(--line)`. Drawer on wide: border-left only, no shadow.
- Header: opaque, 1px bottom border, no blur.
- Focus: `outline: 2px solid var(--accent); outline-offset: 2px; border-radius: inherit`, `:focus-visible` only. Never auto-focus a tertiary button on load.

### Colour tokens
